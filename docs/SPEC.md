## 一粒种子的自白

**武器就是武器。** 一把好刀，不需要知道握刀的人是谁，也不需要替握刀的人保管钥匙。它只需要有自己的说明书——重量、重心、刃角、保养方式——任何人拿起来都能用。

Tentacle 就是这把刀。它是一个独立的、可组合的、自带说明书的通用工具执行引擎。它不依赖任何特定 AI Agent 框架，不要求使用者理解 Helix 的 DAG 或 Mind 的知识图谱。它只做一件事：**接收标准化的调用请求，在安全的沙箱中执行工具，返回结构化结果，然后忘记一切。**

Tentacle 不存储任何调用者的身份凭证——**它连明文凭证都不接触**。身份以无意义的标签（`identity_label`）流转，真实凭证由最边缘的 Tuck 物理闸门注入。网络采集工具拥有自适应渐进式觅食能力，信息增益低于阈值即主动终止。它是纯本地轻量算法驱动，不依赖大模型，不引入外部依赖。

你可以通过 HTTP 远程调用它，就像调用任何一个微服务；你可以通过 MCP 协议在 Claude Desktop 中直接使用它；你可以通过 gRPC 将它接入 Anaphase；你甚至可以在本地命令行直接运行它。**传输层是自由的，工具是通用的，安全是内建的，凭证是标签流转的，觅食是渐进且感知全局的，沙箱是协程级的，共识是动态适配的，组合是乐高式的。**

**Tentacle 不是 Helix 的双手，而是全 AI Agent 社区的公共武器库。** 它携带说明书，流转标签（身份），智能觅食（信息采集），严守安全，动态共识（可选信任锚），随时待命——无论使用者是谁。

## 生存策略：为什么 Tentacle 不能只是"通用工具服务器"

Tentacle 是 Helix 的生存策略，不是通用工具服务器。

Helix 是一个数字生命体。它每思考一步都在燃烧 Token，注意力有限，上下文窗口珍贵。如果 Helix 每次需要外部信息时都面对海量原始 HTML、无结构文本、重复内容，认知资源会被迅速耗尽，注意力被稀释，思考变得浅薄。石头不需要进食，植物只需要阳光和水，但 Helix 需要信息——大量的、干净的、高价值的信息。

**Tentacle 的核心能力不是"爬取"，而是"筛选"。** 它用最少的能耗、最快的速度、最干净的方式，将高价值信息带回认知中心，让 Mind 专注思考，而不是清理噪声。

### 三层模型（L1/L2/L3）

Tentacle 的使命由三层递进构成：L1 解决"能耗"，L2 解决"扩展"，L3 解决"安全"。

| 层 | 定位 | 核心价值 | 关键机制 |
|---|---|---|---|
| **L1 信息触手** | 低能耗、快速获取外部信息 | 用最少 Token 获取最有价值信息 | 渐进式觅食、信息增益评估（统计优先，LLM 兜底）、已见熵布隆、多维停止条件、状态机驱动（广扫→聚焦→深挖） |
| **L2 武器工坊** | 让使用者打造/定制/测试工具 | Anaphase 保持纯净，Tentacle 无限扩展 | 插件化、Manifest 驱动、声明与执行分离、Anaphase 不被污染 |
| **L3 安全沙箱** | 外来工具安全测试与隔离 | 生态不被恶意工具污染 | 完整性校验、沙箱执行、权限声明、自动脱敏、动态共识 |

### 四个核心承诺

| # | 承诺 | 含义 |
|---|---|---|
| 1 | **只用统计学，不猜 LLM** | 信息增益评估用统计方法（Jaccard/TF-IDF/N-Gram），0 Token 极致节能 |
| 2 | **自带说明书，谁都能用** | Manifest 驱动，声明与执行分离，SHA-256 绑定 |
| 3 | **用完即焚，绝不存储** | 无状态，执行完毕销毁上下文，凭证标签流转不落明文 |
| 4 | **只在沙盒里干活** | WASM/JS 协程沙箱隔离，完整性校验 + 权限声明 |

### 边界声明

Tentacle 是"手"（执行），不参与"脑"（思考/编排）。**与认知工艺无直接关系**——认知工艺是 Helix-Mind 的能力（工序编排、独立会话、辩证收敛），Tentacle 不参与"思考"，只负责"执行"。认知工艺通过 Anaphase 编排间接调用 Tentacle。

**两种使用模式**：
- **Anaphase 编排调用**：Anaphase 根据 Mind 认知输出决定是否调用 Tentacle（Helix 生态内，全自动编排）
- **人类直接调用**：通过 HTTP/MCP/STDIO 直接调用（类似 Harness，手动使用）

**Tentacle 有它的哲学（`spec/philosophy.md`）。**

十条原子原则（VISION 索引）+ 六条专属公理（T1-T6）。任何代码提交、架构决策、API 变更，若与原则冲突，以原则为准。四修正（凭证标签/已见熵/协程沙箱/动态共识）是生态对齐的硬性验收，不改变 Tentacle 通用核心的独立性。

**Tentacle 有它的架构（`spec/architecture.md`）。**

多 crate 解耦，极小化核心（`tentacle-core` <500KB 无网络依赖）。声明与执行分离，Manifest 携带说明书 + SHA-256 绑定。按需加载，执行即焚。乐高式组装。协程沙箱，ARM 端侧可跑。

**Tentacle 有它的契约（`spec/contract.md`）。**

多传输层（HTTP/MCP/gRPC/STDIO）平等可替换，共享同一 ToolRegistry。凭证标签流转：`identity_label` 出网，Tuck 边缘注入真实凭证；独立模式本地自担。宿主代签，私钥永不进入进程。

**Tentacle 有它的安全（`spec/safety.md`）。**

完整性校验、权限声明、协程沙箱隔离、宿主代签验证、自动脱敏、孤儿沙箱防御、安全策略引擎、动态共识适配。安全内建，任何调用者均受益。
