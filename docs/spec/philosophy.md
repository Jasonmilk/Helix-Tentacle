# 哲学卷（spec/philosophy.md）
> **来源**：Tentacle 工程白皮书 v3.4 第一部分提炼
> **性质**：Tentacle 的哲学根基——原则、公理与生态对齐验收

## 一、10 条原子原则（不可变）

| # | 原则 | 一句话解释 |
|---|---|---|
| 1 | **不预载，不应求则不动** | 启动只加载核心骨架；工具懒加载，用完即焚 |
| 2 | **自带说明书，谁都能用** | 每个工具携带完整 Manifest，渐进披露 |
| 3 | **多传输层，多协议共生** | 同一套工具经 HTTP/MCP/gRPC/STDIO 平等暴露 |
| 4 | **零信任凭证：标签流转** | Tentacle 不存储不接触明文凭证；`identity_label` 流转，Tuck 边缘注入 |
| 5 | **沙箱即契约，安全可验证** | 每个工具独立沙箱；完整性校验、权限声明、越权拒绝 |
| 6 | **自适应觅食，信息饱和即止** | 信息增益评估 + 已见熵布隆，边缘价值递减即止 |
| 7 | **异步协程沙箱，ARM 可跑** | worker 池 + 协程协作终止，不在端侧开 OS 线程 |
| 8 | **动态共识适配，独立可用** | Standalone/Helix/MCP；独立模式不返回 503 |
| 9 | **身份与凭证分离** | 凭证由 Tuck 物理保管，Tentacle 只流转标签 |
| 10 | **通用核心 + 生态适配** | Tentacle 面向全 AI Agent 社区；Helix 是其中一个用户 |

## 二、6 条专属公理（延伸）

| # | 公理 | 核心 |
|---|---|---|
| T1 | 不预载，不应求则不动 | 懒加载 + 即焚 |
| T2 | 自带说明书，谁都能用 | Manifest + 渐进披露 |
| T3 | 多传输层，多协议共生 | 核心与传输解耦 |
| T4 | 凭证标签流转，零信任 | `identity_label` 出网，Tuck 注入 |
| T5 | 沙箱即契约，安全可验证 | 独立沙箱 + 权限声明 |
| T6 | 自适应觅食，信息饱和即止 | 信息增益 + 布隆过滤器 |

## 三、生态对齐四修正（硬性验收）

| # | 修正 | 验收标准 |
|---|---|---|
| 1 | 凭证标签流转（Tuck） | 内存 grep 不出明文 Cookie/Token；Tuck 按标签替换 |
| 2 | 已见熵布隆过滤器（Callosum） | 跨会话爬同一关键词，第二次不重复采集已覆盖信息 |
| 3 | 异步协程沙箱（ARM） | ARM 端侧 10 并发 JS 工具不 OOM/CPU 过载 |
| 4 | 动态共识适配 | Claude Desktop 调 Critical 工具弹确认，不返回 503 |

**四修正不改变 Tentacle 通用核心的独立性**——它是"武器与生态握手"的接口，不是绑定。

## 四、哲学裁决示例

| 冲突场景 | 裁决依据 |
|---|---|
| 传输层取舍 | T3 多传输平等 → 不偏爱某一传输 |
| 凭证处理 | T4 零信任 → 永远标签流转，不落明文 |
| 觅食终止归类 | T6 → 200 正常完成，非 4xx 错误 |
| 共识不可达 | 原则 8 → Standalone 终端确认，永不 503 |
| 沙箱实现 | T5 + 原则 7 → 协程级，不在端侧开 OS 线程 |
